# Slice 7: Stop rules

A `stop` rule keeps Claude working (with a loop guard) or shows a warning as the turn ends; failures let the turn end.

## Features

- AC-21.1 a matching block keeps Claude working with the message
- AC-21.2 a matching warn ends the turn and shows the user
- AC-21.5 after three consecutive blocks the turn ends and the user is told
- AC-9.5 a failed stop check lets the turn end and tells the user

## Behavior — EARS

- WHEN a `stop` rule has a simple `pattern`, THE SYSTEM SHALL match it against the transcript — AC-1.4
- WHEN Claude tries to end its turn and an active `block` rule on `stop` matches, THE SYSTEM SHALL keep Claude working and give it the rule's message — AC-21.1
- IF the session transcript is larger than the file read limit, THEN THE SYSTEM SHALL match `stop` rules against the last assistant message — AC-21.1
- WHEN Claude ends its turn and an active `warn` rule on `stop` matches, THE SYSTEM SHALL let the turn end and show the user the rule's message — AC-21.2
- WHEN the same `stop` rule has kept an agent working three times in a row, THE SYSTEM SHALL let the turn end and tell the user which rule kept blocking — AC-21.5
- WHEN the user submits a prompt, THE SYSTEM SHALL reset the stop loop counters — AC-21.5
- IF the check of a `stop` rule fails, THEN THE SYSTEM SHALL let the turn end and tell the user the check failed — AC-9.5

## Quality Gates

- Loop guard never lets a stop rule hold a turn beyond three blocks
- Baseline: subagent stops (`classic.SubagentStop`) behave like main-session stops
