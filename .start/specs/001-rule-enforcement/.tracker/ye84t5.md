# Slice 6: Turn-end review of warn conditions

`warn` rules with an `llm_evaluate` condition are reviewed at each agent's turn end; findings are shown to the user, who can send them to Claude.

## Features

- AC-8.2 the turn's calls are evaluated at turn end and findings are shown to the user, who can send them to Claude
- AC-9.2 a failed warn check or review lets work continue and tells the user

## Behavior — EARS

- WHEN an agent's turn completes, THE SYSTEM SHALL evaluate that turn's queued calls against the active `warn` rules with evaluators and show any finding to the user — AC-8.2
- WHERE the session has a surface with a prompt box, WHEN the user chooses to send a finding, THE SYSTEM SHALL place it in the prompt box for the user to send — AC-8.2
- THE SYSTEM SHALL never send an evaluator finding to Claude or start a turn without the user's choice — AC-8.2
- IF the session has no surface, THEN THE SYSTEM SHALL record evaluator findings in the session log only — FR-8 assumption
- WHEN the user submits a prompt, THE SYSTEM SHALL report the main session's still-queued calls as not reviewed and empty that queue — AC-8.2
- IF a turn queues more than 50 calls for review, THEN THE SYSTEM SHALL review the first 50 and report the rest to the user as not reviewed — FR-8 assumption
- IF the batch review of an agent's turn fails (no result, an unparseable reply or an error), THEN THE SYSTEM SHALL tell the user the review failed and send nothing to Claude — AC-9.2

## Quality Gates

- NFR-5 (review rules): ≥ 90% caught, ≤ 5% flagged on the labelled set
- No turn is ever started by cc-enforcer

## Assumptions and open questions

- [ASSUMPTION] Review cap: at most 50 calls per agent turn (Standing).
